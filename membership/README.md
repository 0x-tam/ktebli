# Ktebli account and membership

This Next.js app runs at `https://ktebli.vercel.app/account` as part of the same Ktebli website. The static homepage and proposal routes stay on the root site; its `/account` rewrite forwards to a separate internal Vercel deployment with Next's `basePath: "/account"`. Neon Managed Auth and a separate Neon Postgres project/branch hold accounts, profiles, catalogues, saved notices, in-app alerts, subscription entitlements, and a one-credit-per-paid-cycle ledger. Existing Supabase proposal generation and its OpenRouter spending controls remain in place.

**Release state:** the same-site account pages are deployed; billing, proposal credits, and matching remain off. Anonymous routing and protected API denial have passed live checks. Real signup and OTP delivery, authenticated account flows, Stripe purchase/webhook handling, email alert delivery, and a live scheduled refresh have not passed qualification. Alerts are in-app. PPA has complete bilingual listing discovery and progressively verified details; UNGM has only 11 curated official Lebanon notice URLs, not complete discovery. CDR automated access remains blocked. Report those scopes separately.

## Local development and database roles

1. Use the user's chosen, separate Ktebli Neon project. Create a branch before migrating; do not run the migration on production or an unrelated existing project.
2. Enable Managed Auth on that branch, add the preview origin as a trusted domain, and enable email/password plus email code authentication. Set its URL and a random 32+ character cookie secret in `.env.local`. Production requires configured custom SMTP; shared development delivery is not a production email guarantee.
3. Run `CONFIRM_MEMBERSHIP_BRANCH=yes node --env-file=.env.migrations.local --import tsx scripts/migrate.ts` with the **direct** `DATABASE_URL_UNPOOLED` of the branch migration owner. The migration script is versioned and transactionally idempotent. Runtime migrations never run on request paths.
4. Create dedicated non-owner logins with no superuser, role-creation, or BYPASSRLS privilege. Grant only `membership_runtime` to the app login, `membership_billing` to the billing login, `membership_worker` to the offline matching job, and `membership_ingest` to the public-catalogue job. Use `NOINHERIT` for the ingest login. Set pooled app/billing/worker URLs and a direct `INGEST_DATABASE_URL`; the runner takes a session advisory lock. Do not put migration-owner, worker, or ingestion URLs in the public Next deployment.
5. Install exact locked dependencies (`npm ci`) and run `npm run dev`. Set `APP_ORIGIN` to the exact origin. Browser secrets are never supplied using `NEXT_PUBLIC_` variables.

The Next server verifies the session on every protected route. Transaction-local identity and RLS restrict runtime reads/writes. The billing credential is necessarily present in the webhook deployment and can alter billing tables; it cannot access profiles or the catalogue. This is least-privilege separation, not a guarantee against a compromised application server.

The separate Ktebli project is `green-shadow-66380714` in Frankfurt (`aws-eu-central-1`). Membership schema `001`, additive catalogue checkpoint migration `002`, narrow Mawred source migration `003`, and Managed Auth are provisioned on `dev-membership` (`br-falling-thunder-b19x4p2p`). Compute is fixed at 0.25 CU with the account's default five-minute suspension policy. The live setup checks are recorded in `reports/neon-provisioning.json`; signup, sign-in and email delivery remain unverified. Billing, matching and proposal credits remain disabled.

Local credentials are split between ignored, permission-600 files: `.env.local` contains the pooled app/billing logins and Auth cookie secret, `.env.worker.local` contains the offline matching worker login, `.env.ingest.local` contains the direct public-catalogue login, and `.env.migrations.local` contains the direct migration-owner URL. Deploy only the app/billing/Auth configuration to the public Next app. The root `.env.local` is unchanged. Load each job's own environment file explicitly.

## Catalogue and matching jobs

Crawler is its own package at `crawler/`; follow its README for source access rules and commands. Do not run it inside the existing Render document-conversion service. Capture `records` and `coverage`, then run `npm run catalog:import -- <artifact.json>` using only the job credential. PPA promotion requires both locale streams to be complete and their counts to match. Import is an upsert and never deletes records missing from partial crawls. Source dates are SQL dates; no unstated midnight deadline is invented. Full source text/locale evidence remains reviewable.

Run `npm run match:run` only after verified import and paid matching qualification. It selects at most 20 stale profile/content versions, only for active paid members and verified details fetched in the past 24 hours with a known non-conflicting deadline strictly after today. A date-only notice due today might already have closed, so it is excluded conservatively. The paid-call reservation rechecks entitlement, profile revision and source hash/freshness; post-call match and alert writes recheck again. Unknown, stale, award/direct-agreement and conflicting notices never produce alerts or spend matching credits. Unknown-deadline notices disappear from browsing after 30 days without a refresh. Catalogue pages use stable cursors and search across the database.

Matching is disabled until a **separately authorized allocation within the remaining existing cumulative spend limit** is configured. `MEMBERSHIP_TYPESAFE_API_KEY` never falls back to engineering TypeSafe or customer OpenRouter credentials. `MEMBERSHIP_MATCHING_BUDGET_USD=0` prevents calls. Reservations are durable, cumulative, never reset daily/monthly, and unique per user/opportunity/profile/content version; unknown provider outcomes stay charged against the reservation. The pinned `jev-1.13.0` price was checked against [official TypeSafe models](https://docs.typesafe.ai/models) on 2026-10-05: $0.042 per million input tokens, output free, at most 64k total input tokens. Code enforces a reservation of at least $0.003, covering even 65,536 input tokens, and records usage-derived actual cost. The budget counts the full reservation, including failures. Matching automatically stops after 2026-11-04 until pricing qualification is refreshed. This does not authorize increasing or resetting the existing cumulative customer budget.

The prepared GitHub Actions workflow `.github/workflows/membership-catalogue.yml` runs only public-source ingestion, never matching or billing. It is **not active** until the reviewed code is on the repository default branch, an environment-scoped `MEMBERSHIP_INGEST_DATABASE_URL` secret is approved and installed with its exact branch endpoint verified, one manual run passes, and repository variable `MEMBERSHIP_CATALOG_REFRESH_ENABLED=true` is set. The daily schedule is 02:17 UTC with a 90-minute cap. PPA refreshes both locale listing streams, attempts up to 300 recent locale details and 100 older ones in separate passes, and imports the complete paired recent snapshot before attempting the historical pass. Curated UNGM rechecks only its 11 allowlisted official detail URLs; Mawred rechecks one official Production Awards page. Source-specific compressed checkpoints survive ephemeral runners, use revision checks, and preserve progress on failure; no missing records are deleted. A checked-in workflow alone does not prove an observed scheduled run or freshness. GitHub may disable public repository schedules after inactivity, so monitor source health through `npm run ops:status` and workflow runs. CDR remains manual/blocked.

The ingestion role can access only public opportunities, source-run coverage and checkpoints. Its URL is absent from the Next deployment and separate from the matching worker. Run one crawl/import per source snapshot. Matching claims and budget reservations are concurrency-safe; failed claims need operator review and remain reserved. `npm run ops:status` reports source coverage, checkpoint age/size, catalogue freshness and matching reservations without exposing profile data. Oversized matching contexts are recorded per version in `matching_blocks` before any paid call and do not stop later records. No daily refresh promise applies until the workflow is activated and a scheduled run is observed.

## Stripe and the proposal credit bridge

Use Stripe **test mode first**. Configure a $20 USD recurring monthly Price (quantity one, no trials/discounts) and a dedicated non-default customer portal that allows cancellation/payment-method updates but no price/quantity changes. Set Stripe keys, `STRIPE_MEMBERSHIP_PRICE_ID`, and `STRIPE_MEMBERSHIP_PORTAL_CONFIGURATION_ID`. Register `https://ktebli.vercel.app/account/api/billing/webhook` for `invoice.paid`, subscription updated/deleted, charge refunded, dispute created, and checkout session expired. Only exact paid $20 recurring invoices linked to this app's canonical Checkout/customer/subscription create entitlements. Refund/dispute tombstones prevent delayed invoices from restoring reversed credits.

For credits, configure a separate random `MEMBERSHIP_BRIDGE_SECRET` in both deployments; set Supabase `MEMBERSHIP_REDEEM_URL` to `https://ktebli.vercel.app/account/api/bridge/redeem` and app `SUPABASE_MEMBER_VALIDATE_URL` to Supabase `member-validate-intake`. Deploy the additive Supabase migration plus the modified payment webhook and the new validation function. The public static handoff path stays blank until review and deployment have passed. It is a deployment-owned allowlist value, never read from browser parameters. Set `PROPOSAL_SITE_ORIGIN` to the same Ktebli root origin.

A member starts a proposal from the board. The existing intake validates it, then sends its opaque token in a URL fragment to the membership app. Tokens are removed from the address bar and temporarily kept in sessionStorage for the sign-in handoff. Membership verifies the account's email against the pre-intake and Stripe customer. One active-cycle credit is reserved, and exact checkout parameters/expiry are persisted before Stripe creation. The paid webhook first validates and consumes the original intake token, then redeems the bound credit against canonical Stripe data, persists a receipt, and creates the original proposal order. Full-price guest orders are unchanged. A retry after token consumption or redemption resumes the same session/order. There is no distributed transaction across Stripe, Neon, and Supabase; failed events must be retried and reviewed.

Each paid cycle supplies one $20 credit, without stacking or rollover, applicable to $149/$299/$449 tiers. A completed paid session is judged by canonical charge time, not webhook delivery time. Unpaid expired sessions release reservations via Stripe events, the next checkout attempt, or `npm run credits:reconcile`. The reconciler recovers missing session IDs from Stripe, only releases confirmed expired/unpaid sessions or an exhaustively absent session after persisted expiry plus one hour, and reports settled sessions requiring replay. It never releases a redeemed credit. A membership reversal immediately attempts to expire its open unpaid proposal checkout. Unconfirmed expiration remains durably pending on the revoked credit for `credits:reconcile`, including recovery of a session created before its ID was saved. A payment that won the settlement race is marked `paid_review` for operator refund/order reconciliation; the job reports these records and never silently reactivates their credits.

Unexpected membership webhook failures log a bounded event ID/type and error code, without bodies or secrets. Stripe retains failed deliveries for operator replay. For a paid proposal event that cannot finish, inspect that Stripe event/session, the Neon reservation and Supabase receipt/order, fix the blocking condition, and replay the original event. Never create a second checkout or manually restore a redeemed credit to work around a partially finished order. Refunds of an already-redeemed membership cycle need operator review of the discounted proposal; automatic credit reversal does not claw back delivered work.
