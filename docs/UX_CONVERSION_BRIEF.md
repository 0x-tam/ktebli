# Ktebli conversion and simplicity brief

## Working prompt
Redesign Ktebli as one calm, straightforward service. Help a first-time visitor understand what they can do, what they will receive, what it costs and the next action without learning our internal workflow. Prioritize completing a proposal purchase from an existing opportunity; provide a clear second route to finding opportunities in Lebanon. Preserve the warm cream/forest identity and editorial typography. Simplify structure and copy before adding decoration. Use one primary action per step, short summaries, familiar labels and progressive disclosure. Use user-initiated dialogs only for bounded decisions or help, with accessible dismissal and focus behavior. Never use surprise popups or hide price, uncertainty, required consent or limitations that affect purchase.

## Journey decisions
- Homepage: concise value proposition, primary Start a proposal, secondary Browse opportunities. Four locks remain a clear differentiator, explained once. Remove repetitive long feature/type/comparison narratives; preserve useful sample with optional details and factual package scope. Prices explicit, three succinct packages, detailed inclusions expandable. Existing section anchors remain useful.
- Browse/account: board is the purpose. Remove repeated disabled membership sales banner from the top of all pages; offer Membership details quietly, keep active billing/credit controls functional. Search and type filter front and center; secondary filters behind an accessible disclosure with active filter count/state. Compact rows give title, source, deadline/status and prepare CTA; full details on demand. Keep all-opportunity default and server filtering/pagination/cache contracts.
- Authentication: only Sign in / Create account as primary modes. Email code is a secondary alternative, not competing third tab. Specific task-oriented copy, compact form, visible progress and errors. Do not change provider/session/security logic or trigger real emails in testing.
- Proposal intake: Link → Package → Your details → Review & pay. Name/email essential; individual/organization supported, optional background progressively disclosed. One concise opportunity preview, source-backed autofill and editable details. Keep ambiguity confirmation/blocker recovery and all server clearance/payment checks. Every step tells user what happens next. Review clearly shows opportunity/title/deadline/package/price/deliverables/delivery expectation.
- Paid order: primary current action (essential brief or progress/downloads) first; additional background and source evidence collapsible. Avoid repeated preparation/status paragraphs. Preserve essential fields, provenance warnings, revisions, deadlines and delivery gate.

## Guardrails
No backend/schema/auth-provider/payment contract changes, no hidden required fields, no invented proof or guaranteed wins, no customer-facing model names, no new heavy dependencies. No fake urgency or conversion tricks. Four locks cover Ktebli proposals for same opportunity; required issuer text preserved. All current feature flags remain as configured. 44px targets, 16px mobile inputs, keyboard focus, semantic controls, reduced motion. Avoid nested modals. Preserve user input on disclosure changes, async errors, navigation/back.

## Acceptance
Inspect actual diff. Relevant tests/type/lint/build/format pass. Fresh Sol high review of auth/checkout-adjacent changes. Browser desktop/mobile walkthrough with screenshots: homepage, intake first/package steps and editing/back, auth modes/errors without submission, board filters/details/prepare with synthetic local fixture if no session, paid order rendering with isolated fixture or explicit limitation. Never claim live paid/auth verification without doing it. Deploy only scoped reviewed files via existing safe release procedure.
